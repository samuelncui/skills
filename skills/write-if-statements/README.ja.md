# if 文の書き方

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

新しい条件ロジックの作成、分岐の多い関数のレビュー、動作を変えないコードの簡素化に使うスキルです。目標は判断を読みやすくすることで、`if` の数を減らすことではありません。

## インストールと使い方

Skills CLI またはホスト対応のインストーラーを使います。

```sh
npx skills add samuelncui/skills --skill write-if-statements
```

ライセンス、参考資料、サンプルを含むディレクトリ全体を保持してください。ガイドを読むだけなら他のスキルや Python は不要です。付属サンプルの実行にのみ Python 3 が必要です。

コーディングアシスタントに `$write-if-statements` の使用を依頼するか、ホストで選択します。関連コード、呼び出し元、期待する動作、利用可能なテストコマンドを渡してください。依頼の例：

- 「このクライアントのリトライ条件を書いて。一時的なエラーで試行回数が残っている場合だけ再試行し、単純に保って境界をテストして。」
- 「このルーティング関数をレビューして。参照表に置き換えても最初の一致を優先し、不要な処理を実行しない性質が保てるか説明して。まだ編集しないで。」
- 「戻り値、例外、後片付けを変えずに、このハンドラーのネストを浅くして。回帰テストを追加し、関連テストを実行して。」

成果物は、範囲を明確にしたレビューまたはパッチ、構造を選んだ理由、テスト結果と未検証の範囲です。明快な単純分岐は残すことがあります。疑わしいバグの修正は、動作を保つリファクタリングと区別します。

## サンプルを試す

[実装](examples/conditionals.py)と[テスト](examples/test_conditionals.py)を併せて読み、このスキルのディレクトリで実行します。

```sh
python3 -B -m unittest discover -s examples -p 'test_conditionals.py' -v
```

7 つのテストメソッドで、ガード節の結果と後片付け、例外の伝播、条件が重なる順序付きルール、省略される条件評価、選択されたハンドラーだけの実行、残す価値のある単純な論理積を確認します。標準ライブラリだけで動きますが、検証対象は教材のサンプルであり、利用者のアプリケーションではありません。

## 制約と参考資料

順序付きの条件分岐が辞書と等価とは限りません。判断を移動すると、処理や例外のタイミング、観測する状態が変わることがあります。[意味を変えてしまう落とし穴と一次資料](references/semantic-traps.md)を参照してください。エージェント向け手順は [SKILL.md](SKILL.md) にあります。
