# Study Notes

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

読者が本当に必要とする学習ツールを作ります。解説ノート、統合クイックリファレンス、簡潔なキーワード索引、決定木を、単独または組み合わせて選べます。原稿にはネイティブ LaTeX を使い、レンダリングはインストール済みの `bilingual-pdf` スキルが担います。

## 選べる 4 つの形式

| 形式 | 読者の疑問 | 出力 |
| --- | --- | --- |
| ノート | 「これはどういう意味で、どう動くのか？」 | `notes.pdf` |
| 統合クイックリファレンス | 「用語や作業は覚えている。関連する考え方は何か？」 | `quick-reference.pdf` |
| キーワード索引 | 「関連する概念はどこにあるか？」 | `keyword-index.pdf` |
| 決定木 | 「今わかっていることを踏まえ、次に何をすべきか？」 | `decision-tree.pdf` |

既定ではノートとクイックリファレンスを作ります。クイックリファレンスは、正規の概念、別名、キーワードからの案内を、単一のソート済み見出し語一覧に混在させます。読者が先にキーワード部か概念部かを選ぶ必要はありません。独立したキーワード小冊子は任意であり、必ずもう一度検索しなければならない第 2 の場所ではありません。

## 自身の使い方を題材にした学習サンプル

[オリジナルの教材ソース](examples/source.md)は、この 4 つの形式の選び方と作り方を説明しています。[ソース対応表](examples/source-map.json)、ネイティブ原稿、PDF、プレビューは、すべて `examples/` の下にあります。

- [ノート](examples/notes.pdf)：解説と、選択の具体例
- [統合クイックリファレンス](examples/quick-reference.pdf)：項目を混在させた単一の検索先
- [キーワード索引](examples/keyword-index.pdf)：自動生成される簡潔な参照先一覧
- [決定木](examples/decision-tree.pdf)：自然な質問、選択肢、確認の手順、方法

サンプルは、このスキル自体を題材として使い方を示します。独立した利用ガイド、[執筆ガイド](references/authoring.md)、[ネイティブ API](references/native-api.md)、[ビルドガイド](references/rendering.md)、[レビューチェックリスト](references/review-release.md)は、読みやすい Markdown として提供します。

## レンダラーのインストール先を調べる

ホストを通じて `study-notes` と `bilingual-pdf` の両方をインストールします。実際のインストール先をそれぞれ確認してください。互いに無関係なパスに置かれる場合があるため、隣接したインストールを想定しないでください。

```sh
export BILINGUAL_PDF_SKILL="/path/reported/by/host/bilingual-pdf"
export STUDY_NOTES_SKILL="/path/reported/by/host/study-notes"
```

`bilingual-pdf/assets/paralleltext.sty` が、ページ寸法、フォント、段落の整列、ページをまたぐ継続、図、役割、表紙、レンダリングチェックを管理します。このスキルの `studytools.sty` は、ネイティブのレコードとナビゲーションを追加します。依存関係をダウンロードせず、別のレンダラーも含みません。

共通のレイアウト API は、二言語スキルの独立したネイティブ・言語・設定リファレンスを参照してください。ネイティブビルドには XeLaTeX、latexmk、および文書に記載されたフォントとパッケージが必要です。Python はリポジトリ／PDF の品質確認用に任意で使えます。このスキルに JSON 原稿アダプターはありません。

## 必要な形式だけをビルドする

`examples/` を新しいプロジェクトへコピーし、確認したスキルのパスを保持したうえで、教材原稿を利用許可のある内容に置き換えます。そのプロジェクト内で実行します。

```sh
make BILINGUAL_PDF_SKILL="$BILINGUAL_PDF_SKILL" STUDY_NOTES_SKILL="$STUDY_NOTES_SKILL"
make PRODUCTS='decision-tree' BILINGUAL_PDF_SKILL="$BILINGUAL_PDF_SKILL" STUDY_NOTES_SKILL="$STUDY_NOTES_SKILL"
make PRODUCTS='notes quick-reference keyword-index decision-tree' BILINGUAL_PDF_SKILL="$BILINGUAL_PDF_SKILL" STUDY_NOTES_SKILL="$STUDY_NOTES_SKILL"
```

最初のコマンドはノートとクイックリファレンスを選択します。選択した関連ノートを参照する文書は、そのノートを先にビルドしてください。省いた関連文書への壊れた外部リンクを残してはいけません。相対パスの文書間リンクを使う PDF は一緒に置いてください。この種のリンクへの対応はビューアーによって異なります。

持ち運べるネイティブプロジェクトとして渡す場合は、必要な `paralleltext.sty`、`studytools.sty`、`study-tree.tex`、`study-graph-components.tex`、原稿と設定ファイル、ライセンスを含めてください。納品用のコピーを作ることと、別のインストール済みレンダラーを保守することは異なります。[ビルドガイド](references/rendering.md)には、latexmk を直接使うコマンドと依存関係の確認方法があります。

## 単一の検索レジストリ

意味のある下位項目も含め、正規の概念は一度だけ宣言します。読者が覚えている語、別名、略語は、該当する概念または下位項目へ直接案内します。生成される参照には、関連する題名や文脈と実際の参照先ページが含まれます。関連文書の情報が利用できる場合は、その文書の識別情報と節／ページも示します。

検索上の同一性は明示し、ソートキーとは分けて扱います。同じ見出し語グループを意図的に共有するレコードはまとめて表示しますが、句読点の正規化だけで異なる意味を統合してはいけません。同等の正規概念の解説がない用語集の定義は、単なる「関連」リンクとして捨てず、実質的な内容として残します。

同じネイティブのレジストリから、統合クイックリファレンスまたは簡潔な索引を生成できます。グループ化、別名、複数の参照先、下位項目、短い柱、ナビゲーションフックは[ネイティブ宣言のリファレンス](references/native-api.md)を参照してください。

## 方法へ導く質問

[ネイティブ決定グラフ](references/graph-components.md)で自然な質問を作り、必要な前提をその場に示します。A/B/C を順に調べ、最初に一致する条件を選びます。自動生成する N1、N2 などの参照と内部の意味キーを分離します。各解法には、答えに至る理由、操作、確認を記します。

不足情報は可能な限り質問の横で補います。情報収集が実質的な作業になる場合だけ、独立した経路を設けます。すべての質問に不明経路は必要ありません。循環には引き継ぐ状態、進展、終了条件を示します。共通レンダラーの質問は青、解法は緑という役割を保ちます。

## 長い段落と再利用可能な表示

`ParallelSetup{paragraph-flow=breakable}` と `ParallelParagraph` を使い、必要な段落では `[flow=keep]` で上書きします。ページをまたぐ本文を、独自の分割不可ボックスで囲まないでください。基準となるレンダラーは、対訳版と選択言語版の継続に対応し、次の単位の前に整列を復元します。大きすぎる分割不可ブロックはエラーとなり、内容の切り捨てや縮小は行いません。

利用側のプロジェクトでは、テスト済みのスキルのリビジョンを固定し、非公開の内容、メタデータ、薄い互換アダプターを自分のプロジェクトに保持してください。不足する汎用機能は共有レンダラーへ追加し、独自のレイアウト分岐を保守しないようにします。

## レビューと納品

ソースの網羅範囲、解説の質、現実的な検索経路、決定経路、リンク、実際の PDF ページは、それぞれ確認します。根拠なしに完全性や独立監査の実施を主張しないでください。選択した PDF、ソース対応表、持ち運べる編集可能なプロジェクトを渡し、合格、不合格、未実施のチェックを報告します。

ネイティブ TeX と latexmk 設定はコードを実行します。shell escape の無効化だけでは、ファイルアクセスを隔離できません。非公開のソース、氏名、識別子、出典記録を公開サンプルに含めず、外部処理や公開の前に必要な許可を得てください。オリジナルのコードと内容は [MIT ライセンス](LICENSE)であり、依存関係にはそれぞれのライセンスが適用されます。
