# テストワークフロー

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

コード変更に必要なテストの選定と保守、回帰不具合の調査、遅い検証手順の改善に使う skill です。プロジェクト既存のテスト基盤を優先し、リスクに応じて検証範囲を選びます。必須のリリース条件は維持します。

## 使い方

ホストの skill インストーラーで `testing-workflow` をインストールするか、ディレクトリ全体をコピーしてください。PDF skills への依存はありません。例えば、次のように依頼します。

- 「testing-workflow を使ってパーサーの修正を検証し、回帰テストを残して、影響を受ける呼び出し元も確認して」
- 「このテストスイートが遅い原因を調べ、重要な検証範囲を失わずにコストを減らす方法を提案して」

変更内容またはリポジトリ、既知の不具合、必須の検証、利用禁止のサービスや費用上限を伝えてください。短い検証範囲の説明、必要な実行可能テスト、成功・失敗・スキップ・実行不能・未実行を区別した報告が得られます。詳しい手順は [agent ワークフロー](SKILL.md)と[コスト・性能の参考資料](references/cost-and-performance.md)にあります。

## サンプルを試す

[タグ正規化の実装](examples/tags.py)と[テスト](examples/test_tags.py)を読み、インストールした skill のディレクトリで実行してください。Python 3.11 以降を使い、外部パッケージは不要です。

```sh
python3 -B -m unittest discover -s examples -p 'test_tags.py' -v
```

3 つのテストメソッドで通常の入力、冪等性、Unicode のケースフォールディング、不正な入力を検証します。unittest がアサーションを実行し、失敗時の終了ステータスを返します。教材用の例であり、製品の検証結果ではありません。既存のテスト基盤に合わせて応用してください。

自動テストだけで事実、言語、見た目、アクセシビリティの正しさは証明できません。外部サービス、有料実行、公開、明示的に除外された評価には、それぞれの許可条件が引き続き適用されます。[MIT ライセンス](LICENSE)。
